# KStore v2 — Full E-commerce Rebuild Plan

## Context

The v1 codebase (storefront, admin, orders, server-side pricing from the previous session) is solid but: auth is OTP-only, checkout requires login, payments are manual bank/mobile-money, the Supabase project is dead, and the home page has no admin-controlled content. The user's v2 spec: Google + password auth with reset, guest checkout, email tracking links, Stripe + COD payments, reviews, admin CMS (categories, banners, analytics, users, payments), account settings, and a structured home page. Decisions made: **new cloud Supabase project, Stripe (not PayPal), OTP system deleted, demo mode deleted** (single DB-backed code path, per the no-dead-code rule).

## Phase 0 — Database foundation (blocking; needs user's new Supabase project)

User runbook (I write it into README): create free project → paste `NEXT_PUBLIC_SUPABASE_URL/ANON_KEY` + `SUPABASE_SERVICE_ROLE_KEY` into `.env.local` → I apply SQL.

Since the DB is brand-new, **rewrite `supabase/migrations/20260803121029_init.sql` in place** (never deployed anywhere) — no legacy residue:
- `payment_method` enum: `('stripe', 'cash_on_delivery')`; `payment_status`: `('pending','paid','cod_pending','refunded','cancelled')` — manual proof statuses gone
- `orders.user_id` **nullable** (guests) + `tracking_token uuid default gen_random_uuid()` + `stripe_session_id text`
- **`reviews`** table: rating 1–5, comment, `unique(order_id, product_id)`, `is_published`; RLS: public read published, insert only by order owner with paid/delivered order (subquery policy)
- **`banners`** table: `placement ('hero','promo')`, title, subtitle, image_url, cta_label/href, sort_order, is_active; public read / admin write; new public `banners` storage bucket (policies mirror `product-images`)
- `store_settings`: drop `bank_*`/`mobile_money_*` columns, add `terms_html`
- Drop `otp_codes`, `payment-proofs` bucket and their policies (Stripe auto-confirms; COD needs no proof)
- RLS: add admin-read-all to `reviews`; orders keep owner/admin policy (guest reads go through server routes via service-role)
- Seed (`20260803121029_seed.sql`): keep the 12-product catalog; add 2 hero slides from product imagery; no bank fields

**Demo mode deletion:** remove `lib/data/demo.ts`, `lib/auth/demo-session.ts`, `isDemoMode()` branches in `lib/env.ts`, `lib/data/{catalog,orders,orderAdmin,auth}.ts`, `lib/data/pricing.ts`, `proxy.ts`, `app/auth/callback`. Storefront keeps the same look via the seeded DB.

## Phase 1 — Auth v2: Google + email/password + reset

- Rework `components/auth/LoginForm.tsx` (reuse its Card/Banner/Google-icon): Google button (already functional via `signInWithOAuth` → existing `app/auth/callback/route.ts`), email+password sign-in/register toggle, "Forgot password?" link. No own Google client ID needed (Supabase provider handles it; One Tap stays optional via existing env).
- New `app/(auth)/forgot-password/page.tsx` → `resetPasswordForEmail(redirectTo: /auth/reset)`; new `app/auth/reset/route.ts` (exchange code, redirect to account security tab); change password via `auth.updateUser` in account settings.
- **Delete:** `lib/auth/otp.ts`, `app/api/auth/otp/**`, OTP constants. Keep `app/api/auth/logout`, `proxy.ts` session refresh.

## Phase 2 — Guest checkout + tracking links

- `app/api/orders/route.ts`: drop the 401 gate — logged-in → `user_id`; guest → null + `tracking_token`; always email confirmation; guests additionally get tracking link `/track/{order_number}?t={token}` (mailer gains link param via `getSiteUrl()`).
- `lib/data/orders.ts:createOrder`: insert via `createAdminClient()` (guests can't satisfy owner-RLS) — input is zod-validated and server-priced, so the trusted client is safe. Keep `.gte(stock, qty)` guarded decrement.
- New `app/api/track/route.ts` (POST orderNumber+token → service-role lookup → sanitized order JSON) + `app/track/[orderNumber]/page.tsx` with a lean `OrderTracker` component (status timeline, reuses `StatusBadge`/`DeliveryStatusText` — read-only, distinct from OrderDetailView, no duplication).
- Logged-in users: existing `/orders` + `/orders/[id]` = in-app tracking (unchanged).

## Phase 3 — Payments: Stripe + COD

- Add `stripe` dep. New `app/api/checkout/stripe/route.ts`: creates a Checkout Session from **`resolvePricedItems()` output** (server prices only — reuses Phase-1-v1 security work); success returns to order page (or guest track page) which calls `.../confirm` to retrieve the session and mark paid + event. Optional `STRIPE_WEBHOOK_SECRET` webhook route as belt-and-braces.
- `components/store/CheckoutForm.tsx` rework: guest/customer fields, method picker = Card (Stripe) or COD; split into `components/store/checkout/PaymentMethodPicker.tsx` + `OrderSummary.tsx` (each file < 300 lines).
- Delete payment-proof UI: `PaymentProofCard.tsx`, `app/api/orders/[id]/payment|proof` routes, proof upload block in `OrderDetailView`. `PAYMENT_METHOD_LABELS`/schemas trimmed to two methods.

## Phase 4 — Reviews

- `lib/data/reviews.ts`: summary (avg/count), product reviews, reviewable products for a user (paid/delivered orders, not yet reviewed), upsert, admin list + publish toggle.
- New shared `components/shared/StarRating.tsx` (display + input modes — Astryx has no Rating component; one reusable unit, no duplicates) + `components/store/ReviewForm.tsx` (Astryx Dialog).
- Product page: rating summary + review list + eligibility-gated "Write a review". Account dashboard: "To review" + "Your reviews". Admin `/admin/reviews` (Table + publish toggle).

## Phase 5 — Admin CMS + analytics

- `AdminShell` nav: + Categories, Banners, Reviews, Users.
- `/admin/categories` + `/api/admin/categories` (CRUD, mirrors products-route pattern; `CategoryForm` dialog).
- `/admin/banners` + `/api/admin/banners`: hero slides + promo banner management with new shared `components/admin/ImageUploadInput.tsx` (uploads to `banners` bucket) — **also replaces ProductForm's comma-URL image input** (upload to `product-images`).
- `/admin` analytics upgrade: keep stat cards + add top products (aggregate order_items), orders-by-status, recent orders (Astryx `Table`); `/admin/users` (profiles + order counts); `/admin/orders` gains payment column + Stripe receipt link.
- `/admin/settings` becomes a real `SettingsForm` (store name, tagline, support email, currency, shipping, delivery notes, about/terms HTML) — replaces the "edit in Supabase" note; RLS admin-write already exists.

## Phase 6 — Storefront v2

- Home: `HeroSlider` (Astryx `Carousel` fed by `banners` placement=hero; falls back to featured-product imagery) — **replaces HomeHero (deleted)**; categories section (exists); featured (exists); **Deals** section (`compare_at > price` query in catalog.ts); **New arrivals** (`created_at desc`); admin-controlled `PromoBar` (placement=promo).
- Wire the already-built `TrustStrip`; add free-shipping `ProgressBar` to CartView; About copy from settings; new `/terms` page (`terms_html`).
- Account dashboard with Astryx `TabList`: Profile (edit name/phone → new `/api/account/profile` PATCH), Security (change password), Orders (existing), Reviews. Keep `LogoutButton`.
- End-state cleanup pass: delete every now-unused import/file; every file ≤ 300 lines.
